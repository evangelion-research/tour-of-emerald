# Exercises

Reading is not enough: you learn a language by *writing* it. These exercises
give you a problem, a hint if you want one, and a full solution to compare
against.

## How to work through them

1. Read the problem and **try it yourself first** — in a fresh `.rald` file.
2. Stuck? Read the hint.
3. Compare your solution with the one given. It doesn't have to match exactly;
   if it runs and prints the right thing, it's correct.
4. Predict the output *before* you run, then check.

## Runnable solutions

Every exercise has a complete, runnable solution in
[`code/`](code/), with its expected output in
[`expected/`](expected/). These mirror the lesson programs in
[`../code/`](../code/). Solutions are also shown inline in each group's page,
hidden behind a "Show solution" fold so you can try first without peeking.

## A note on being stuck

Being stuck is normal — it's the state right before understanding. The most
useful things you can do, in order:

1. Re-read the corresponding lesson, especially its **Key ideas**.
2. Run your program and read the *exact* error or output. Emerald's messages
   point at the line and the reason.
3. Make the problem smaller: solve it for one tiny input by hand, then teach the
   computer that one step.
4. Peek at the hint, then at the solution.

There is no prize for suffering in silence.
